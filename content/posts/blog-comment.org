#+TITLE: 给博客加上评论区
#+DATE: <2026-07-29 Wed 00:00>
#+TAGS[]: 博客 评论 Artalk

从零开始，给这个静态博客加一套评论区。前后折腾了整整一天，中间走了一段弯路，最后落定在一个成熟方案上。

* 自建还是用现成的

一开始想自己写。参考 Derek Sivers 的 [[https://sive.rs/shc][Static HTML comments]] 思路——评论写入时预渲染成静态 HTML，读取时零数据库查询。用 Go 写了一个 ~200 行的服务端，JSON 文件持久化，in-memory cache。

功能依次加上：

- 邮件通知（Mailgun SMTP, 465 端口 TLS）
- 嵌套回复（parent_id + 递归渲染）
- 删除评论（X-Admin-Key 鉴权）

跑在 Docker 上，通过 CF Tunnel 暴露到 comments.tianheg.co。

但自建的坑比预想的多：

- 时区问题（Alpine 没装 tzdata，时间显示 UTC）
- <ol> 序号不好看
- 嵌套缩进不生效（内联 style 被 Tailwind prose 覆盖）
- 子回复渲染在父级 div 外面（DOM 结构不对）
- 表单跨域跳转

修到第三个问题时我意识到：**写一个能用的评论系统和写一个好用的评论系统，中间差着几个数量级的工作量。**

Artalk 这个项目关注很久了，Go 后端，SQLite，功能齐全，中文友好。不再犹豫，切过去。

* 部署 Artalk

Artalk 容器跑在同一个 Docker VM 上（192.168.8.2:23366），数据挂 volume，SQLite 单文件持久化。

```yaml
# artalk.yml 核心配置
host: "0.0.0.0"
port: 23366
locale: zh-CN
timezone: Asia/Shanghai
site_url: "https://tianheg.co"

db:
  type: sqlite
  file: ./data/artalk.db

email:
  enabled: true
  send_type: smtp
  send_addr: noreply@tianheg.co
  smtp:
    host: smtp.eu.mailgun.org
    port: 465
    username: i@tianheg.co
```

管理员通过命令行创建：

```bash
docker exec artalk artalk admin \
  --email i@tianheg.co \
  --password <password> \
  --name tianhe \
  -c /data/artalk.yml
```

后台在 [[https://comments.tianheg.co/]]。

* 前端集成

Hugo 的 partial 模板引入 Artalk：

```html
<link href="/dist/Artalk.css" rel="stylesheet">
<script src="/dist/Artalk.js"></script>
<script>
Artalk.init({
  el: '#Comments',
  pageKey: '{{ .Permalink }}',
  pageTitle: '{{ .Title }}',
  server: 'https://comments.tianheg.co',
  site: 'Tianhe Gao',
  darkMode: 'auto',
})
</script>
```

这里遇到一个坑：博客有 CSP，限制了跨域加载资源。Artalk 的 JS/CSS 从 comments.tianheg.co 加载被 CSP 拦截。

修法：让 blog 的 Cloudflare Worker 代理 /dist/Artalk.\* 到 comments.tianheg.co，变成同域加载，CSP 的 'self' 允许通过。

* 备份

Artalk 的数据全部在 SQLite 文件里，纳入每日备份脚本：

```bash
ssh root@192.168.8.2 "tar czf - -C /data artalk"
```

SQLite 单文件备份和恢复都非常简单。

* 几点感受

**自建的成本不在写代码，在维护。** 评论系统看着简单，但邮件通知、反垃圾、嵌套回复、管理后台、暗色模式——每一个都是要花时间打磨的细节。成熟方案替你付了这些成本。

**Artalk 的 Go 单二进制 + SQLite 设计很对胃口。** 和自建方案同样的技术路线，但人家做了八年，一万多次提交。不该自大的时候别自大。

**CSP 是好事。** 虽然拦了我一下，但这种安全默认严格的态度是对的。加个同域代理就好了。
