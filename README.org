** 站点理念与内容策略
几条决定内容怎么增删改的原则，动内容前先读：

- *链接会变，不做重定向。* 技术类、时效性强的文章会随时间推移、我理解程度的加深而改链接，或与其他文章合并、简化。如果你发现文章链接 404 了，最好在博客上找找。我不做重定向------维护重定向列表不是一件能坚持很久的事。博客的此时此刻，代表了我此时的状态；内容的改变反映了我状态的改变。
- *内容是活的。* 站上的内容不会静态不变，它永远在变化，永远反映我思维方式的改变、我情绪的变化。它是旺盛生命力的代表------没有它，我只是一个人；有了它，我能冲破现实的枷锁，和无尽的想象力相伴，让自己不断探索生命的奥义。
- *不配图。* 有时候一图胜万语，但我的博客不需要。
- *整理是长期的。* 合并同类文章、删除无价值文章、简化标签分类------自 2022-11-15 起持续在做。
- *写作人称。* 文章中的「他」不单指男性，也包括女性；写作中作者退居二线，多以「你」称呼。
- *内容定位。* 主要是随时学习的记录与生活感想；外语电影首选外语作标题，中文放在文中。

*** TIL header 标记
扁平化结构下，子分类用 =#+HEADER= 标记，不建立子目录：

#+begin_src org
,#+TITLE: Git merge 与 rebase
,#+HEADER: Git
#+end_src

分类页按 header 分组展示，右侧边栏可折叠筛选。支持多 header（空格分隔）。

*通用约束：*

- ❌ 不能有大写字母
- ❌ 不能有空格
- ❌ 不能有中文标点
- ❌ 避免无意义编号（=001.org=, =note1.org=）

*** TIL 笔记边界纪律（2026-09 对照 blackglory.me 树形笔记结论）
Blackglory 的笔记 = 每主题单页深层可折叠概念树（如 Linux 页 199 节点、最深 6 层、700KB）。对照后确认：*TIL 的分类 + #+HEADER 扁平结构是正确设计，不重建深目录树，不把主题合并成巨页*。理由：定位靠检索（Pagefind + 语义搜索），不靠层级导航；扁平结构 URL 稳定、git/STATUS 粒度清晰；巨页移动端不可读。

三条边界纪律：

1. *边界后置、就地生长* --- 同主题碎片别急着开新文件或建目录，优先合进现有文件做 =*= 小节。只有文件内部层级到 4 层以上、且各小节需要独立引用时，才拆成新文件。
2. *检索宽容* --- 一条内容同属多个 header 时随手放任意一处即可，不纠结归属（Pagefind 兜底）。多 header 参数支持真实多归属，但默认不为此花时间。
3. *深链可用* --- Goldmark 按标题文本生成锚点（=#标题文本=，CJK 原样保留；重复标题自动加 =-1= 后缀），文件内小节可被 URL 直达。需要固定锚点时用 ={#custom-id}= 属性。

触发阈值（动边界的信号）：

- header 组 > ~60 篇且成员互相引用频繁 → 合小为大，内部 =*= 树结构化
- 单文件 > ~6 个平级 =*= 小节且语义独立 → 拆文件

*** 内容头字段（org 关键字）

文章（=org/posts/=）：

#+begin_src org
,#+TITLE: 编程技术一览，程序员练级攻略
,#+DATE: <2022-11-06 15:02:00>
,#+TAGS[]: 技术
#+end_src

TIL（=org/til/=）必带整理状态与日期（状态 2026-09-01 起 / 日期 2026-09-10 起，全库强制）：

#+begin_src org
,#+TITLE: 40个计算机科学核心概念（通俗解释）
,#+DATE: <2026-04-06 17:39:49>
,#+STATUS: draft
,#+HEADER: Programming
#+end_src

- =#+STATUS:= 取值 =draft=（AI 生成/代写，未经人工整理）或 =reviewed=（人工复核过）
- =#+DATE:= 语义是*首次入库时间*：新建用当天时间；历史文件取 git 首次提交时间
  （=git log --diff-filter=A --follow=），无 git 历史时回退文件 mtime。2026-09-10 已全库补齐
- 日期驱动 =/til/= 的「最近新增」排序；posts/til 下缺 =#+DATE:= 的页面会被*跳过不构建*
  （严格模式下直接让构建失败，见「部署」）
- AI 代写一律 =draft=；用自己的话复核/补充后改 =reviewed=
- =#+HEADER:= 是 TIL 的子分类标记（见上节）

*** 内部链接与 wikilink

正文引用其他笔记，两种写法都支持：

- *Wikilink*：=[[git-rebase]]=、=[[git-rebase|显示文字]]=、=[[笔记本保养#小节]]=
- org 链接：=[[/til/software/git-rebase/][显示文字]]=

wikilink 依次按 *文件名 → 完整标题 → 标题主名（=——=/=：=/=|= 之前那截）* 解析
（=scripts/org2site/export.el=）。代码块与行内代码里的 =[[…]]= 不会误解析。

*写错名字也不会产生死链*（三层保证）：

1. *渲染兜底* —— 解析不到时渲染成「站内搜索」链接（虚线下划线 + 悬停提示），
   读者看不到 =[[…]]= 原文，也点不到 404
2. *构建告警* —— 构建末尾打印未解析 wikilink 的处数与样例（=build.el=，0 处时静默）
3. *构建即闸门* —— 站内死链由 =scripts/org2site/verify.py= 第 5 项拦住，
   它跑在 =build.sh= 末尾且受 =set -e= 约束；CI 另开 =ORG2SITE_STRICT=1=，
   未解析的 wikilink 直接让构建失败

*写法约定*：

- 站内引用用 =[[文件名]]= —— 文件名是唯一稳定的标识（标题会改、文件名不改），解析也最不容易歧义
- 要中文显示：=[[laptop-maintenance|笔记本保养]]=
- 指小节、站外链接、静态文件仍用 org 链接或裸 URL

*反链*：**内容页（posts / til）** 末尾自动渲染「引用这篇的」（=build.el= 的 =org2site--backlink-index=）。
根页面（about / search / watch / links…）是站点功能性页面，**不加**这一区 —— 底部挂一串
「引用这篇的」是噪声。但索引照旧收录根页面作为**来源**：它们引用内容时，那条引用会出现在
被引页的反链里。构建时全站扫一遍建索引（O(n)，**不是每页扫全站**），只做 incoming；每条附上
引用它的那句话（linked mention），超过 6 条折叠。解析直接复用导出层的 =org2site--wikilink-url=，
所以反链与页面里真实渲染出来的链接永远一致。

*外链*：正文里的站外链接（=http(s)://= 且主机不在 =tianheg.co=）一律
=target="_blank" rel="noopener noreferrer"=，在新标签页打开；站内链接（相对路径、锚点、
=mailto:=、指向本站域名的绝对链接）保持原样。判定在导出层 =org2site-link=，按链接元素的
=:raw-link= 主机名判断，不改内容。代码块里手写的 =<a>= 与 =static/= 下的手写 HTML 页面不经过这里。

*仍然没有*：链接悬浮预览（=PagePreview.ts= 已随 Hugo 管线删除）、=/graph/= 图谱页（线上 404）。

*** 分层与尺度（2026-10-18）
样式表 =scripts/org2site/static/style.css= 仍是单文件、零 class（契约见文件头注释）。

*层序（=@layer=）*：=tokens → base → layout → components → pages → utilities=

- 同层内按源码顺序 + 特异性竞争；*跨层后者胜，且与特异性无关* → 改层归属 = 改全局优先级。
- 只有「必须无视特异性、一定要赢」的规则才放 =utilities=（焦点环、触屏点击区、存量 class 兜底）。 本次踩过两次：正文链接下划线压过目录的 =#TableOfContents a=；iOS 防缩放规则把 =/til/= 筛选按钮从 13px 顶到 16px（页面高 5px）。两处都靠指纹回归抓出来并归位。

*尺度*：=--text-*=（12 档）/ =--space-*=（12 档）/ =--radius-*=（4 档），全部是*纯别名*（值与原字面量逐字节相同）。

- 尺度表按「现状台账」命名，不是「理想档位」：实际用到的字号仍有 11 档 （12/13/14/15/16/17/18/20/24/30/36px），与上面「字号阶梯（正文 16 / 条目 15 / 元信息 13）」 的约定存在漂移；要不要归一属于后续独立决定，本次重构不动视觉。

*零视觉变化的验证手法*：=scripts/org2site/style-fingerprint.js=

- 逐元素取 35 个 computed 属性 + 几何 + 树路径，对 6 页 × 2 视口（1280×900 / 412×915）× 2 配色（light/dark）= 24 组算哈希；重构前后 24 组一致即视为渲染等价。
- 本次 S1（尺度）与 S2（分层）都以它验证：S1 24/24 一致；S2 修完两处层归属后 23/24 稳定一致， 余 1 组为「视口切换时滚动条瞬时出现」的测量假象（=scrollHeight= 两侧相同）。
- 踩过的注意点：字体未加载完会影响行高（等 =wait_for_load= 后再 0.7s）；切配色后再等 0.4s； 视口切换可能滞后一帧导致 =clientWidth= 差 15px；=text-underline-offset= 在无下划线的元素上是噪声，不作判据。

*** 站外链接死链扫描（=node scripts/check.mjs external=）

> *每周一 05:00 由 cron 自动跑*（job =e58bcb517f3d=，no_agent，脚本
> =~/.hermes/scripts/blog-external-links-weekly.sh=）：有真死链（404/410）就投出死链段
> 与修法，没有就投一行打卡简报。下面的命令仍可手动跑。

扫 =org/= 里所有外链（org 链接 + 裸 URL，跳过代码块），并发探测后分类报告。 只有 *404/410* 算死链；5xx、代理到不了、401/403/429、DNS/超时都不算死，分开列。

- 请求带真实 Chrome（Windows）指纹（UA + Sec-CH-UA + Sec-Fetch-* + Referer），避免被 WAF 当爬虫； HEAD 先行，HEAD 不干净或结果为 4xx 时用 GET 复核，405/406/412 这类反爬响应再换朴素 Accept 重试一次
- 传输层用 *curl* 而不是 Node 内置 fetch ------ 本机（PVE + Tailscale MagicDNS + CGNAT）跑 undici 会大批 =UND_ERR_CONNECT_TIMEOUT=，同一批 URL curl 秒开。别改回 undici
- 本机出口走 mihomo（=http_proxy=<内网代理地址>:7892=），代理到不了上游时会直接吐 502 ------ 那是网关的锅， 跟源站死活无关，脚本会再试直连，仍不通归入「到不了」，不判死
- *已确认非死链账本* =~/.cache/blog-external-links/verified.txt= —— **不在仓库里**（2026-10-19 迁出）：探测到 2xx 即自动记一行 =YYYY-MM-DD <URL>=，之后默认跳过探测，报告末尾单列「✅ 已确认非死链」区；超 90 天自动复核，复核发现已死的撤下账本并照常报警。机器维护 + 每次扫描都可能改写（4300+ 行），放仓库里只会产生 commit 噪声；=BLOG_EXTERNAL_LEDGER= 可覆盖路径
- 已知被 WAF 挡死 / 有意保留的历史链接写进 =scripts/data/external-link-ignore.txt=（一行一条，子串匹配）
- 缓存与进度在 =.hermes/external-links/cache.json=（不进版本控制）；死链会顺带查 Wayback 存档

*** 新建内容工作流程
1. 根据内容类型选择 =org/posts/= 或 =org/til/= 下的正确分类
2. 按命名规范创建 =.org= 文件，写 =#+TITLE:= / =#+DATE:= 等关键字（子分类用 =#+HEADER:=）

4. 内容完成后提交即可 ------ CF Workers Builds 会跑同一条 =build.sh=（关键词索引每次部署重建；语义索引由每周一 04:00 的 cron 独立重建，见「语义搜索索引」节）

*** 关键词搜索（PageFind）

- 由 =build.sh= 第 2 步调 =pagefind_extended --site <输出目录>= 生成，每次部署重建
- 只有带 =data-pagefind-body= 的页面进索引；列表页带 =data-pagefind-ignore=
- 中文没有 stemming（PageFind 的限制），搜索命中靠字面匹配

*** 语义搜索索引

- =/search/= 的 AI tab 由构建时预生成的 embeddings 驱动
- =node scripts/embed.mjs= 调 Cloudflare Workers AI（BGE-M3）生成全站页面向量 →
  =static/pagefind-semantic/embeddings.bin=（L2 归一化，提交 git）
- Worker 运行时只嵌入 query + dot product，无冷启动、无 KV 缓存
- *2026-10-10 起：改内容不再随发布重跑 embed*。语义索引由 cron
  =~/.hermes/scripts/blog-semantic-index-weekly.sh=（每周一 04:00，no_agent）全量重建、
  单独提交并 push。代价：新内容进语义搜索最多滞后一周（关键词索引不受影响）。
  无内容变更时静默跳过；可手动 =bash ~/.hermes/scripts/blog-semantic-index-weekly.sh --dry-run --force= 预演。

** 部署

- *平台*：Cloudflare Workers（=wrangler.jsonc=）
- *构建命令*：=ORG2SITE_STRICT=1 bash scripts/org2site/build.sh public=
- *输出目录*：=public/=
- *链路*：=git push= → Forgejo → GitHub 镜像（自动）→ **CF Workers Builds 自动构建部署**，
  约 2–4 分钟。*本地绝不跑 wrangler*（=wrangler dev/deploy= 一律不用）
- *严格模式*：CI 里 =ORG2SITE_STRICT=1= 让两类问题**卡住构建** —— 未解析的 wikilink、
  缺 =#+DATE:= 被跳过的页面（后者意味着文章静默不上线）。本地不加该变量则不拦
- *预检*：=build.sh= 第 0 步跑 =node scripts/check.mjs unicode= 的 ERROR 级
  （全角括号落在链接语法位会静默吞链接），离线排查可 =ORG2SITE_SKIP_PRECHECK=1= 跳过
- 验收：=curl -s https://tianheg.co/ | head= 看新内容，或查 =public/= 产物。
  **别只凭 push 成功就报「已上线」**
