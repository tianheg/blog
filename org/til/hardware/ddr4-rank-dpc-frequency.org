#+TITLE: DDR4 内存的 Rank、DPC 与降频
#+DATE: <2026-10-26 Mon 12:32>
#+STATUS: draft

买服务器内存时，「32G 2400」这三个数字是不够的。同样标着 32GB PC4-2400 的条子，插满之后可能只跑 1866。差别在 Rank 和 DPC。

** Rank 与 DPC

- *Rank*：共享同一组 64 位数据总线完整宽度的颗粒集合。1R / 2R / 4R 靠片选信号（CS）切换，同一时刻只有一组占用总线，但所有组的引脚都并联在同一条线上。
- *DPC*（DIMM per Channel）：每条内存通道插几条模组。

频率由这两个变量共同决定：*每条通道几条 × 每条几 Rank*。

** 为什么 Rank 多会降频

颗粒并联在同一组信号线上。Rank 越多，线路的*容性负载*越大，RC 时间常数增大，信号的上升沿和下降沿变慢。DDR 是同步接口，每个时钟周期要完成采样，信号到得慢就必须留更长的建立时间——时序余量被吃掉，只能降频来换回来。

这是纯电气特性，跟 CPU 强弱、芯片组定位无关。

** 降频规则

DDR4 在双通道、四通道服务器平台上的大致规律：

- 1DPC + 1R/2R → 最高频
- 1DPC + 4R（LRDIMM）→ 最高频
- 2DPC + 1R → 最高频
- 2DPC + 2R → 降一档
- 2DPC + 4R → 降两档

具体档位以 Intel 内存配置指南和 JEDEC 表为准，不同平台和固件版本会有差异。规律本身（Rank 与 DPC 都是负相关因子）不变。

** LRDIMM 用延迟换容量

LRDIMM 条上有一颗 *iMB*（isolating Memory Buffer），站在内存控制器和颗粒之间重新驱动信号。对控制器而言，每条 LRDIMM 只呈现一个「伪 rank」的负载——不管条上实际是 2R 还是 4R，控制器看到的负载都一样小。

这就是 LRDIMM 能在有限 PCB 面积上塞进 4R / 8R 的原因，也让它在 1DPC 时能跑满频率。

代价是多了一级缓冲，延迟增加约 1–2 个时钟周期。

对比 RDIMM：只有一颗寄存器芯片分担地址/命令负载，数据线仍然是颗粒直连，容量上限低但延迟更直接。

** 降频是全系统统一的

Intel 内存控制器要求所有通道同频。只要有一个通道跑在低档配置（例如 2DPC + 4R），整个系统统一降到那个频率——即使其它通道只插了一条。

推论：*不平衡配置照样降频*。4 通道板插 6 条时，有两个通道被迫 2DPC，全系统取最保守档位。所以「插得少反而跑得快」在 Quad Rank 内存上很常见：

- 4 条（每通道 1 条 4R）→ 满频
- 6 条 → 因部分通道 2DPC 而降频
- 8 条（每通道 2 条 4R）→ 再降一档

** 怎么识别

看条上标签，不要相信卖家描述：

- ~4DRx4~ / ~8DRx4~ → LRDIMM（四 / 八 Rank）
- ~2Rx4~ / ~1Rx8~ → RDIMM 的常见规格
- 速度码里的 ~LD~（如 ~PC4-2400T-LD1~）→ Load-Reduced
- 三星型号：~M393~ 开头多为 RDIMM，~M386~ 开头多为 LRDIMM

LRDIMM 与 RDIMM 电气不兼容，服务器板通常两种都吃，桌面/工作站板一般只吃 UDIMM 或 RDIMM。

** 决策规则

*容量优先于频率。* 虚拟化平台里，多 64G 容量远比多 400MT/s 有用——内存不足会直接 OOM 或触发 swap，频率低 20% 只是慢一点。ZFS 的 ARC、多个 VM 同时运行都吃容量，不吃带宽。

*平衡配置优于凑数配置。* 4 通道板的最优是 4 条（每通道 1 条）或 8 条（每通道 2 条）。6 条这类配置容量上去了，但频率和通道交错都不完整，属于「能跑但不优」。

*延迟与容量的取舍要按用途定。* LRDIMM 的缓冲延迟对批量吞吐影响很小，对延迟敏感的数据库或高频交易才有意义——那种场景本来也不该用 LRDIMM。
